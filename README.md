# 沧衡纪：东方架空历史演化模拟器 v1.15.0

一个纯前端、确定性的东方架空历史观察沙盒。你不直接统治国家，而是按季推进时间，观察人物欲望、家族传承、政治制度、资源流通、迁徙、疾病、知识、外交与战争共同写出的历史，并在少数节点用有限“天命”轻推世界。

在线试玩：[oriental-history-simulator.vercel.app](https://oriental-history-simulator.vercel.app/)

当前产品版本为 **1.15.0**，权威存档仍为 **schema 4**，两者彼此独立。开启新世界时可从两张固定舆图中选择：**82 州 / 10 海域的私人舆图**，或 **68 州 / 10 海域的完全架空参赛舆图“云海八荒”**。两者共用人物、家族、政治、经济、战争、海洋、Situation 与入世规则。

schema 4 将真实发生的 Simulation Fact 与面向玩家展示的 Chronicle 分开；军权危机、继承危机和战争进程都从真实事实形成、转阶段与结案。“当世三问”优先连续追踪这些局势，人物也会把战争、任免、婚姻和关键转折留在记忆、盘算与传记中。玩家可以随时入世一名人物，每季定下一项符合身份和处境的行动，再由同一模拟系统结算。

v1.15.0 把世界书页、收藏、史册、对象史卷、持续局势与“何故与证据”收进同一受控页面栈。打开任一阻塞卷页会可靠停表，沿史卷或局势查看原因后可按原路返回；已经关闭的创建、续读、导入或收藏读取也不会稍后夺走当前世界。十种卷页共用焦点、Escape、遮罩和移动安全区规则，四档视口已验证单弹层、无横向溢出和关键 44px 触控。本版不改模拟、schema 4、旧档或世界 hash。

v1.10.0 新增统一“设置”卷页、原创程序化东方声景与十类经合并的语义音效；四季纸色、水面、河流、海岸、海纹、选中和按下反馈也完成一轮收笔。声音默认关闭，所有声音、画面、动态和界面密度设置只属于观察者，不改变世界种子、季度、Fact、Chronicle 或世界哈希。

v1.10.1 是不改玩法、平衡和存档格式的工程收口补丁。观察选择、人物盘算投影与自动化文本快照已从页面壳拆入纯视图模块；纪年与世界哈希也从季度引擎中分离。依赖门现在区分真实运行时循环和仅在类型检查中存在的聚合债务，个人版与参赛版构建同时受产物体积预算和 GitHub CI 保护。

v1.1.0 把第一条人物权力链从“条件说明”推进成真实行动：有独立统军之志的副将会先联络本军将校，或向主帅、主君、家主请求明确背书；答应、观望和拒绝都会改变关系、资源、人物经历与后续审查。正式请令后，朝廷可能换帅、以名位安抚，或因军权风险撤下副将之职。人物档案会直接写明“谁向谁开口、对方如何回应、军职发生了什么”，不再只显示抽象支持值。

## 明天怎么试玩

推荐使用桌面 Chromium 浏览器。进入项目目录后运行：

```bash
npm install && npm run play
```

Vite 会尝试自动打开本地页面；若没有自动打开，请访问终端显示的 `http://127.0.0.1:...` 地址。

首次试玩建议按这条 20～30 分钟路线：

1. 在开篇页先选一张舆图，再选择推荐种子，点击“开启新纪”。第二个世界可体验“云海八荒”的内海与关隘结构。
2. 跟随自动出现的“三眼读图”：先看山河，再认疆界，最后推进一季并打开一条史事的“为何如此”。随后点地图右上的齿轮打开“设置”；声音默认关闭，可在这里主动开启声景，也可调整动态、地图气氛、界面密度和全屏。
3. 阅读底部“本季变化”：人口、粮食、财富是权威季度总账，右侧最多三件事只来自刚结束的一季；点击数字可切换对应叠层并查总账因果。
4. 再按 `N` 推进到完整一年；点击虚线朱砂高亮的州域，查看这一季受影响的地方与人物。
5. 观察“当世三问”如何连续数季保留同一问题；点击带“局势题”的卡片可直接打开对应卷宗。先读史家判断和下一观察，再展开历史凭证；只有想看公式、贡献值和原始 Fact ID 时才打开最底部的 `Simulation Audit`。
6. 在“当世三问”选择“关注局势”，再打开“观察台”确认它以同一 Situation ID 留在关注簿；普通人物、家族、政权与地区仍可独立关注。
7. 开启自动演化，尝试 2×、4× 或 8×；受关注局势形成、转阶段、核心人物死亡或结案时会精确停表，并可从暂停原因直达同一卷宗。战争、权力更替、疫病与重大史事仍可按独立规则暂停。
8. 从舆图或人物名录选一位人物，点“以此人入世”并打开“所图”：普通人物会看到经营关系、争取机会与表明立场；副将会多一项“副将行事”，地方长官则把泛化的争取机会换成“开仓赈济 / 减免本季赋”。定下一件事再推进一季，结果会写清谁做了什么、花了多少、实际改变了什么；随时可以离开或换人，但不会因此多出本季次数。
9. 按 `H` 打开天下史册，筛选史事并拖动时间轴查看当时的领土格局；愿意改变世界时，再尝试一次有限“天意”。
10. 试玩结束前打开“世界收藏”，给当前世界命名；再复制一个独立分支或导出 JSON，确认它能从开篇页重新读取。

### 推荐种子

| 种子 | 开局主题 | 适合观察 |
|---|---|---|
| `沧衡-甲子` | 山河初醒 | 均衡开局，适合第一次熟悉地图、人物与因果追问 |
| `潮生商路` | 海潮东来 | 港口、海贸、舰队、航路和海洋政权 |
| `孤城疫年` | 孤城疫年 | 迁徙、疾病输入、地方卫生与国家韧性 |

相同种子和相同操作序列会产生相同的权威世界哈希。不同的查看、筛选、关注和回看行为不会改变模拟结果；天意干预会生成带凭证的新历史分支。

## V1 试玩能力

### 更可控的观察

- “当世三问”按人物、国势与天下矛盾三个阅读尺度优先选取可见 Situation；某一尺度没有合适局势时，才回退人物、政权、战争、疾病、外交、海权或地方压力等即时线索。
- 新入选问题至少保留 3 个显示季度。任期结束后，也只有高出 20 分的临界 Situation 连续两个相邻季度保持领先才会换题；三题组合还会惩罚重复类型、政权、地域与核心人物，减少同一主体占满视野。
- 正在追踪的 Situation 结案后会额外显示一季结果回响；开放局势低于可见性门槛或对象已经消失时则安全让位。卡片会显示起始时间、已追踪季度和最近转折。
- “观察台”以稳定 Situation ID 保存局势关注，并在形成、阶段变化、核心人物死亡与结案这些权威 Fact 出现时提醒、停表和直达同一卷宗；普通对象关注以及战争、权力更替、疫病、史事重要度规则继续独立工作。
- 人物、列国、世家和军旅名簿可搜索、筛选与排序；默认“值得关注”会逐项写明近季史事、持续局势、官职、军令或军需依据，点击即可回到原史事、原局势或对象档案。
- 首次新世界先用三步读图导览建立“山河 → 疆界 → 季度因果”的最短观察闭环；地图上的“读图”入口可随时重开。观察台另有五项进阶清单。
- 舆图会随缩放在概览、区域与近观三层之间稳定切换：先看政权、首都与主力，再补重点城港和普通军旅，最后展开州名与流线。移动端点中对象先显示四问速览；上划看全卷，下划或点空白返回地图，被速览遮住的对象会自动让出位置。
- 底部季报严格读取本季账本与 `lastTurn.eventIds`，不会把旧史混入“本季要事”；相关州域在下一季到来前保留低调朱砂描边。
- 自动演化支持 1×、2×、4×、8×。快捷键：`N` 下一季、`Space` 开始/暂停、`H` 天下史册、`F` 全屏、`Esc` 关闭当前弹页。
- 观察台底部显示当前产品版本并可手动检查 Vercel 新部署；发现更新时会先暂停并保存当前世界，再由玩家确认重载。后台检查不会中断推演。
- 人物关系页提供可键盘操作的关系星图；世界地图、历史列表和主要弹页保留焦点管理与文本观察接口。
- 人物“所图”按“此人所重 → 放在心上的事 → 眼下所图 → 所行之路 → 最近取舍”阅读；移动端的人物速览可直接进入这一页，无需先翻过生平。
- 任一存活人物都可随时入世或离开。入世面板每季只提供 3～4 项随处境变化的具体行动，明确列出对象、代价、难处与下一观察；副将和地方长官各自只增加与身份有关的一小组选择。决定在推进季度时才结算，单纯进入、换人和查看不会改变世界哈希。

### 更完整的历史回看

- “持续局势”把军权危机、继承危机和战争进程组织成跨季卷宗：默认回答眼下局面、最近转折与后续看点，所据史实和推演底账按需展开。
- 结案卷宗显示起止日期、持续时间、中文结果、最多六个关键转折，以及结案 result Fact 直接证明的任免、领土或制度差量。没有保存的形成期数值会明确标成不可倒推，不用当前值伪造历史。
- 天下史册可按文本、类别、重要度和人物/政权/地区筛选权威史事。
- 时间轴从当前领土状态反向应用已记录的控制权差量，重建所选季度的政治舆图，并标记差量链是否完整。
- 历史舆图是只读镜头，不修改当前世界；回到“当下”后才能继续推演。
- 史事仍可展开结构原因、直接诱因、人物选择、证据与状态变化，并跳转到相关档案。

### 已验证的模拟底座

- 两个正式 MapProfile：私人舆图为 82 州 / 10 海域 / 8 初始政权；“云海八荒”为 68 州 / 10 海域 / 8 初始政权，所有可见地理与政权名称均为完全架空。
- 海岸、岛屿、州域展示点、海域中心、河流导引、港口与航线都由当前 profile 提供；政治层、缩放、点选、军团/水师图标与移动端手势共用同一渲染和命中契约。
- 一回合三个月。季节农业、人口、粮仓、财富、税收、军费、征兵、补给、商品与运输进入季度账本。
- 港口、海路、海峡、舰队、封锁、袭商、造船、宏观登陆，以及粮食之外六类商品的地方产消与真实 Shipment。
- 迁徙、流民和两类动态疾病沿实际贸易、迁徙与军事运输传播；地区、军团与舰队使用精确 S/E/I/R 分舱。
- 农业、军事、工程、医学、商业、航海六类地方实践自然产生，并沿真实人员或货物流传播。
- 人物生命周期、传记、婚姻子嗣、家族支系、有向关系记忆、有界人生记忆、官职、派系、政变、叛乱与副将成长。每人最多保留 16 条人生记忆，其中最多 4 条为难忘旧事；同类反复经历会合并成一条累积记载。
- 军权危机、继承危机与战争进程以跨季度 Situation 持续演化。继承局势以政权为稳定范围，可在换君后保持同一故事身份；战争局势以唯一战争 ID 为范围，明确区分攻守方向，并只把同一战事的会战、州域与海军行动纳入证据。
- 贸易协定、联盟、联姻、朝贡、战争与和谈；税款、关税、贡金和赔款均作为守恒转移结算。
- 调整政权天命、扶持人物、制造灾害、创造关系机缘、保护人物五类有限干预；每次干预保存旧世界哈希、真实差量和完整因果。

## 存档与兼容

- 游戏无需后端，模拟与保存都在浏览器本机完成；IndexedDB 保存自动存档和 V1 本地世界收藏，JSON 用于手动导入导出。
- 三问留任、当前挑战者与仲裁原因是有界的本地观察元数据，按世界种子写入 `localStorage`，并用季度与世界哈希校验是否仍属于当前历史线。它不进入权威世界正文、Fact、Chronicle 或世界哈希；不匹配、损坏或不可用时只会重建三问，不会阻断推演。
- 人生记忆是 schema 4 权威状态的一部分：只读取已封存的类型化 Fact，随存档导入导出，并进入世界哈希与完整校验。史册删减或改变展示文案，不会改写人物记忆。
- 人物盘算的跨季连续簿是另一份本地观察记录：只在种子、季度和世界哈希严格一致时恢复，最多保留 8 个历史分支、25 个恢复点、每分支 16 名代表人物和全簿 64 条取舍对照。它不进入世界正文、存档或哈希；本地数据丢失时只会失去盘算连续性，不会损坏或改变世界。
- 入世人物、未结算行动与离场收束使用独立的本地观察记录，以 seed/turn/hash 精确锚定且限制在 16KiB 内。换人不会刷新已定行动；锚点不合、数据损坏或人物不在时会安全回到普通观察，不会污染世界存档。
- 世界收藏使用独立槽位，不覆盖自动续写；开篇页与世界工具栏都可进入，支持读取、另存、重命名、复制与删除，最多 24 个命名世界。自动存档和 JSON 导出仍是可靠兜底。
- 每个世界以唯一 `mapContentVersion` 绑定精确地图 profile/revision；收藏盘会显示地图名与修订。若当前构建缺少原地图，存档会标记“地图未安装”并保留载荷，可先复制留底，不会用另一张图强行打开。
- 当前世界写入 schema 4。schema 1/2/3 旧档可迁移读取；迁移只封存原历史链边界，不倒推不存在的旧 Fact，也不会扩充旧地图、赠送舰队或重写既有历史。
- 自动存档使用合并式协调器：连续推进只保留最新一代快照、同一时间最多一次写入，并在每 8 季、空闲 5 秒、暂停、切到后台或干预后落盘。
- 本地存档不会自动跨浏览器、跨设备或跨用户同步。清理网站数据、无痕模式限制或浏览器配额不足都可能删除/阻止本地存档，因此重要世界请导出 JSON 备份。

## 发布验证

日常检查：

```bash
npm run test:run
npm run build
npm run build:contest
npm run test:e2e
npm run test:e2e:fux01
npm run test:e2e:trim016
npm run test:e2e:maps
npm run test:e2e:contest
npm run test:audit:maps
```

完整发布门：

```bash
npm run test:release
```

`test:release` 会依次执行单元/系统测试、个人版与参赛白名单构建、桌面 Chromium 试玩、1440/768/640/390 四档页面栈与移动安全区、390×844 与 640×900 移动舆图触控门、Phase A/B/C、人物 Agency、权势叙事、地方施政、双地图 80 季与 V0.3 长程审计。`npm run build:contest` 产出 `dist-contest/`：模块图会拒绝私人内容依赖，产物还会核对版本/allowlist 清单并扫描从私人 profile 派生的 328 项名称与 ID。`npm run test:e2e:contest` 另外验证参赛静态产物只提供公开地图，且遇到缺图旧档时不会覆盖原载荷。

`npm run test:audit:architecture` 用 TypeScript AST 区分 runtime/type-only 依赖，对运行时环、跨层回写、热点文件预算和类型环债务增长直接失败。两种正式构建均限制单个 JavaScript 文件原始体积不超过 560 KiB、JavaScript gzip 总量不超过 410 KiB、CSS gzip 总量不超过 40 KiB。`main` 与 Pull Request 还会在 Node 22 环境中执行 `npm ci`、单测、架构门、双构建和关键浏览器链，失败时保留浏览器产物供复现。

`npm run test:update` 单独验证构建版本标识、游戏内手动检查、模拟新部署、更新前自动保存与移动端入口。参赛产物与源码隔离边界见 [参赛地图构建说明](./docs/CONTEST_BUILD.md)；发布任务与三主循环归属见 [Roadmap](./docs/ROADMAP_VNEXT.md) 和 [功能归属台账](./docs/FEATURE_LOOP_INVENTORY.md)。

模拟内核不使用 `Math.random`。所有不确定性都由“世界种子 + 季度 + 系统 + 实体 + 用途”独立寻址；`window.render_game_to_text()` 与 `window.advanceTime(ms)` 提供确定性的文本观察与自动化测试接口。

## 已知边界

- V1 仍是历史观察沙盒，不提供文明式胜利条件、国家直接控制、武将抽卡、即时战术或兵棋微操。
- 历史时间轴目前精确回溯有控制权差量凭证的领土格局，不是把任意旧季度的所有人口、财政、军队和市场状态完整复活；缺少差量时会显示“有缺页”。
- 世界收藏只存于当前浏览器；云存档、跨设备同步、共享世界、排行榜、在线多人和运行时生成式叙事均不在本次试玩范围。
- 海岸线由州域坐标与通行关系推导，是服务于辨识与策略阅读的架空概括图，不是精密 GIS；稀疏旧档的轮廓会更抽象。
- 桌面 Chromium 与 390×844、640×900 视口已覆盖地图主观察与四层读史路径；复杂关系图仍以桌面体验为先。Firefox、Safari 与真机系统手势尚未进入同等强度的发布回归。
- Phase B 当前完成“军权危机”“继承危机”和“战争进程”三种 Situation 纵切、事实型结案摘要与可见持续局势；Phase C 已完成副将军权链，并交付地方长官“压力 → 施政 → 粮财/动荡变化 → 史事与人生记忆”的第二条小纵切。朝臣、家主、君主身份行动、通用行动 AI 统一、稳定派系分合和朝堂席位图仍按 Roadmap 分阶段进入。
- 局势暂停只认刚结算季度的权威 Situation milestone 与核心人物死亡 Fact，不会把普通张力波动或史册关键词冒充里程碑；未受关注的局势也不会因为这条专用规则停表。

## 技术边界

- React + TypeScript + Vite 负责观察界面；`src/sim` 是无 DOM 依赖、数据驱动的确定性模拟内核。
- 当前仍是一个地图主页与受控卷页/抽屉组成的单页应用；本轮不为了拆代码引入路由器。天下史册等大型二级工具只会在构建分析证明有收益时设立延迟加载边界。
- 当前没有真实运行时循环依赖；`WorldState` 与 Facts/Agency/Situation 之间仍有一个 12 模块的 type-only 契约环，它不会进入浏览器 JavaScript，后续按纯 DTO 边界逐段拆解，不做一次性存档类型搬家。
- 当前版本可完全在浏览器中运行，不需要服务器。只有云存档、跨设备同步、共享世界或排行榜才需要后端。
- 存档保存世界种子、schema、权威状态、Fact 摘要链、事件摘要链和哈希；Chronicle 文案与展示阈值不是事实来源。
- 详细设计与版本落地记录见 [《东方架空历史演化模拟器 System Design Proposal》](./东方架空历史演化模拟器_System_Design_Proposal.md)。
