# 沧衡纪：东方架空历史演化模拟器 v1.26.0

一个纯前端、确定性的东方架空历史观察沙盒。你不直接统治国家，而是按季推进时间，主要观察战争进展与人物 / 朝堂权力变化，并在少数节点入世一名人物或用有限“天命”轻推世界。粮食、人口、贸易、迁徙、疾病和知识继续参与演化，但只作为战争与朝局的背景压力出现。

在线试玩：[oriental-history-simulator.vercel.app](https://oriental-history-simulator.vercel.app/)

当前产品版本为 **1.26.0**，权威存档为 **schema 5**，两者彼此独立。开启新世界时可从两张固定舆图中选择：**82 州 / 10 海域的私人舆图**，或 **68 州 / 10 海域的完全架空参赛舆图“云海八荒”**。两者共用人物、家族、政治、经济、战争、海洋、Situation 与入世规则。

v1.26.0 把人物命途从固定公式收成连续处境：出征只考察与主将、所在地和战线真正相关的人，明确职守直接留守，旧部、亲缘、共同作战与旧怨分别形成不同选择，只有动机冲突时才使用可重放的少量偶然性。普通低风险战斗不再反复抽取具名伤亡；重伤者会退出行营并休养，健康会影响领军资格与指挥。人物档案只保留 1～3 个真正改变处境的节点，死者以“结局”收束，并可从名录的故人筛选或姓名搜索重新找到。

v1.24.1 是不改变模拟与存档的舆图交互修订：区域视野只为主将、集团首领、选中者和当前战局人物常驻姓名，其余人物仍保留可点选的低调点位；姓名会按视觉优先级避让。移动端同时收束战局摘要、地图提示和底部导航，统一触控热区、按下反馈与面板层级，让地图重新成为首要阅读区域。

v1.24.0 把兵力从抽象军团归还给人物：每位符合条件的在世成年人物拥有唯一个人军势，只保留兵力、凝聚和战备三项核心值。行营不再是兵力所有者，只保存主将、参与者、共享军令、路线和补给；总兵力永远由参与人物部曲汇总。战损确定性分回每位参战者，战报封存当时的个人投入、伤亡、集团和指挥关系，日后转投不会改写旧仗。

舆图现在把人作为军事阅读的基本点：总览合并同州人物簇，区域视图展开出征者与领袖，近观则显示所有具名人物和自有部曲。多人出征时只画一条真实行军路线，同行点以短连线表示同一行营。旧 schema 4 存档会先验真，再按旧军团兵力和已有主副将关系确定性迁移，不补造旧战报。

schema 5 沿用 Simulation Fact 与 Chronicle 分层，并新增唯一的人物军势兵力所有权。军权危机、继承危机、战争进程和朝堂权斗仍从真实事实形成、转阶段与结案；观察界面不保存第二套兵力或战局账本。

COMPACT01 是一次机制减法：人物影子账本、三问跨季仲裁器和六种专业地图叠层已经撤下。舆图只保留“疆界、军争、供养、地势”；海军、军令、行军与可核验的预计接敌归入军争，其余后台领域在地区档案、季度事实或供养压力中按需说明。模拟 schema、随机序列和季度领域顺序不因本次观察层收口而改变。

v1.20.1 撤下了持续局势默认阅读层中的“萌芽、发展、临界”“升温、降温”以及张力、势头数值，改为先讲具名人物、地点、行动和实际结果。已有事实会直接进入卷宗；当季没有新的具名行动或实际变化时就如实说明，不再拿阶段变化补成新闻。底层 Situation 状态仍保留在内部演算与测试诊断中，模拟规则、schema 4 存档与世界 hash 均未改变。

v1.20.0 让第一类朝臣真正进入既有政治循环：冬季代入一名在中枢任职、同时领导现存派系的朝臣，可与同国另一派“交换朝中支持”。这项决定和世界自行演化出的结盟共用同一政权的一席名额、同一对象身份与同一门槛，没有玩家加成；成功后同一桩原事会进入联盟承诺、双方恩义、传记、个人记忆、权势账与史册，条件失效或本季落选则保持零状态差量。

v1.19.0 把已有政治内容收成一条可往返的观察线：都城印记、人物手中权势、家族在朝支点、具体史事和朝堂权斗卷宗，都会指向同一个真实派系。已退场派系只留史迹，不暗中改选“继承者”。长纪年审计同时核对高权势首屏可见、地图真实根基、领袖更替和派系分合；两张地图的内容数据也移出主 JavaScript 解析路径，存档和推演规则不变。

v1.10.0 新增统一“设置”卷页、原创程序化东方声景与十类经合并的语义音效；四季纸色、水面、河流、海岸、海纹、选中和按下反馈也完成一轮收笔。声音默认关闭，所有声音、画面、动态和界面密度设置只属于观察者，不改变世界种子、季度、Fact、Chronicle 或世界哈希。

v1.10.1 是不改玩法、平衡和存档格式的工程收口补丁。观察选择、人物盘算投影与自动化文本快照已从页面壳拆入纯视图模块；纪年与世界哈希也从季度引擎中分离。依赖门现在区分真实运行时循环和仅在类型检查中存在的聚合债务，个人版与参赛版构建同时受产物体积预算和 GitHub CI 保护。

v1.1.0 把第一条人物权力链从“条件说明”推进成真实行动：有独立统军之志的副将会先联络本军将校，或向主帅、主君、家主请求明确背书；答应、观望和拒绝都会改变关系、资源、人物经历与后续审查。正式请令后，朝廷可能换帅、以名位安抚，或因军权风险撤下副将之职。人物档案会直接写明“谁向谁开口、对方如何回应、军职发生了什么”，不再只显示抽象支持值。

## 明天怎么试玩

推荐使用桌面 Chromium 浏览器。进入项目目录后运行：

```bash
npm install && npm run play
```

Vite 会尝试自动打开本地页面；若没有自动打开，请访问终端显示的 `http://127.0.0.1:...` 地址。

首次试玩建议按这条 20～30 分钟路线：

1. 在开篇页先选一张舆图，再选择推荐种子，点击“开启新纪”。第二个世界可体验“云海八荒”的内海与关隘结构。
2. 跟随自动出现的“三眼读图”：先看山河，再认疆界，最后推进一季并打开一条史事的“为何如此”。随后点地图右上的齿轮打开“设置”；声音默认关闭，可在这里主动开启声景，也可调整动态、地图气氛、界面密度和全屏。
3. 阅读底部“本季变化”：人口、粮食、财富仍是权威季度总账，但只作为背景；右侧最多三件事来自刚结束的一季。优先打开战事或权力变化，沿“何故与证据”查清原因，再选择相关军团或人物继续看。
4. 再按 `N` 推进到完整一年；点击虚线朱砂高亮的州域，查看这一季受影响的地方与人物。
5. 观察“当世三问”列出的最多三条当前故事；遇到战争问题时点开卷宗，再点“回到舆图看战线”。舆图会自动进入军争层并聚焦真实参战人物：点位直示姓名、自有部曲和行营关系，战局摘要汇总双方与各集团投入；不足三条故事时宁可少列，也不编空泛问题。
6. 可直接在持续局势卷点“关注局势”，也可在“当世三问”关注；再打开“观察台”确认它以同一 Situation ID 留在关注簿。普通人物、家族、政权与地区仍可独立关注。
7. 开启自动演化，尝试 2×、4× 或 8×；受关注局势出现同季具体行动、核心人物死亡或明确结案时会停表，并可从暂停原因直达同一卷宗。只有后台阈值发生变化而没有具体史事时不会打断观察；战争、权力更替、疫病与重大史事仍可按独立规则暂停。
8. 从舆图或人物名录选一位人物，点“以此人入世”并打开“所图”：普通人物会看到经营关系、争取机会与表明立场；副将会多一项“副将行事”，地方长官则把泛化的争取机会换成“开仓赈济 / 减免本季赋”。若在冬季找到一名兼任中枢官、又领导现存派系的朝臣，还可尝试“交换朝中支持”。定下一件事再推进一季，结果会写清谁做了什么、实际改变了什么；随时可以离开或换人，但不会因此多出本季次数。
9. 按 `H` 打开天下史册，筛选史事并拖动时间轴查看当时的领土格局；愿意改变世界时，再尝试一次有限“天意”。
10. 试玩结束前打开“世界收藏”，给当前世界命名；再复制一个独立分支或导出 JSON，确认它能从开篇页重新读取。

### 推荐种子

| 种子 | 开局主题 | 适合观察 |
|---|---|---|
| `沧衡-甲子` | 山河初醒 | 均衡开局，适合第一次熟悉地图、人物与因果追问 |
| `潮生商路` | 海潮东来 | 港口、海贸、舰队、航路和海洋政权 |
| `孤城疫年` | 孤城疫年 | 迁徙、疾病输入、地方卫生与国家韧性 |

相同种子和相同操作序列会产生相同的权威世界哈希。不同的查看、筛选、关注和回看行为不会改变模拟结果；天意干预会生成带凭证的新历史分支。

## V1 试玩能力

### 更可控的观察

- “当世三问”是简单故事入口：从当前开放 Situation 中按阶段、重要度、紧张程度、起始时间与稳定 ID 选择最多三条，不再固定人物 / 国势 / 天下槽位，也不维护任期、挑战者或组合优化。
- 开放局势优先；已经结案的 Situation 最多保留一季回响。仍有空位时只用本季战争或朝堂事实补位，没有具名事实就允许少于三条。
- “观察台”以稳定 Situation ID 保存局势关注；有同季具体行动的形成或动向、核心人物死亡与明确结案会提醒、停表并直达同一卷宗，只有后台阶段变化而没有具体事情时不会中断推演。
- 人物、列国、世家和军旅名簿可搜索、筛选与排序；默认“值得关注”会逐项写明近季史事、持续局势、官职、军令或军需依据，点击即可回到原史事、原局势或对象档案。
- 都城印记会直达当季主导派系；人物“手中权势”、家族“族人在朝”、史事“本事所系朝局”和局势卷的派系参与者使用同一份 ID，点开后不会回退到另一个默认派系。
- 首次新世界先用三步读图导览建立“山河 → 疆界 → 季度因果”的最短观察闭环；地图上的“读图”入口可随时重开。观察台另有五项进阶清单。
- 舆图会随缩放在概览、区域与近观三层之间稳定切换：先看政权、首都与主力，再补重点城港和普通军旅，最后展开州名。四种叠层分别回答疆界与权力根基、陆海军争、地方供养压力和山河地势。移动端点中对象先显示四问速览；上划看全卷，下划或点空白返回地图，被速览遮住的对象会自动让出位置。
- 底部季报严格读取本季账本与 `lastTurn.eventIds`，不会把旧史混入“本季要事”；相关州域在下一季到来前保留低调朱砂描边。
- 自动演化支持 1×、2×、4×、8×。快捷键：`N` 下一季、`Space` 开始/暂停、`H` 天下史册、`F` 全屏、`Esc` 关闭当前弹页。
- 观察台底部显示当前产品版本并可手动检查 Vercel 新部署；发现更新时会先暂停并保存当前世界，再由玩家确认重载。后台检查不会中断推演。
- 人物关系页提供可键盘操作的关系星图；世界地图、历史列表和主要弹页保留焦点管理与文本观察接口。
- 人物“所图”按“此人所重 → 权威目标 → 所行之路 → 最近事实”阅读，目标与计划直接来自 `agencyDecisionSystem`，实际结果来自 typed Facts；移动端的人物速览可直接进入这一页。
- 任一存活人物都可随时入世或离开。入世面板每季只提供 3～4 项随处境变化的具体行动，明确列出对象、代价、难处与下一观察；副将、地方长官和符合条件的派系领袖朝臣只增加与身份有关的少量选择。决定在推进季度时才结算，单纯进入、换人和查看不会改变世界哈希。

### 更完整的历史回看

- “持续局势”把军权危机、继承危机、战争进程和朝堂权斗组织成跨季卷宗：默认只讲最近实事、直接变化和结案状态；此前实事、相关各方与所据史实按需展开，内部阶段和候选结果不进入普通阅读层。
- 结案卷宗显示起止日期、持续时间、中文结果、最多六个关键转折，以及结案 result Fact 直接证明的任免、领土或制度差量。没有保存的形成期数值会明确标成不可倒推，不用当前值伪造历史。
- 天下史册可按文本、类别、重要度和人物/政权/地区筛选权威史事。
- 时间轴从当前领土状态反向应用已记录的控制权差量，重建所选季度的政治舆图，并标记差量链是否完整。
- 历史舆图是只读镜头，不修改当前世界；回到“当下”后才能继续推演。
- 史事仍可展开结构原因、直接诱因、人物选择、证据与状态变化，并跳转到相关档案。

### 已验证的模拟底座

- 两个正式 MapProfile：私人舆图为 82 州 / 10 海域 / 8 初始政权；“云海八荒”为 68 州 / 10 海域 / 8 初始政权，所有可见地理与政权名称均为完全架空。
- 海岸、岛屿、州域展示点、海域中心、河流导引、港口与航线都由当前 profile 提供；政治层、缩放、点选、军团/水师图标与移动端手势共用同一渲染和命中契约。
- 一回合三个月。季节农业、人口、粮仓、财富、税收、军费、征兵、补给、商品与运输进入季度账本。
- 港口、海路、海峡、舰队、封锁、袭商、造船、宏观登陆，以及粮食之外六类商品的地方产消与真实 Shipment。
- 迁徙、流民和两类动态疾病沿实际贸易、迁徙与军事运输传播；地区、军团与舰队使用精确 S/E/I/R 分舱。
- 农业、军事、工程、医学、商业、航海六类地方实践自然产生，并沿真实人员或货物流传播。
- 人物生命周期、传记、婚姻子嗣、家族支系、有向关系记忆、有界人生记忆、官职、派系、政变、叛乱与副将成长。每人最多保留 16 条人生记忆，其中最多 4 条为难忘旧事；同类反复经历会合并成一条累积记载。
- 军权危机、继承危机与战争进程以跨季度 Situation 持续演化。继承局势以政权为稳定范围，可在换君后保持同一故事身份；战争局势以唯一战争 ID 为范围，明确区分攻守方向，并只把同一战事的会战、州域与海军行动纳入证据。
- 贸易协定、联盟、联姻、朝贡、战争与和谈；税款、关税、贡金和赔款均作为守恒转移结算。
- 调整政权天命、扶持人物、制造灾害、创造关系机缘、保护人物五类有限干预；每次干预保存旧世界哈希、真实差量和完整因果。

## 存档与兼容

- 游戏无需后端，模拟与保存都在浏览器本机完成；IndexedDB 保存自动存档和 V1 本地世界收藏，JSON 用于手动导入导出。
- “当世三问”是当前世界的无状态投影，不写入 `localStorage` 或世界存档。旧观察台数据若含三问连续性字段会直接忽略，关注、暂停和导览设置仍正常恢复。
- 人生记忆和人物军势都是 schema 5 权威状态的一部分；军团兵力只是参与者部曲之和的派生缓存，不另行计入人口。
- 人物目标只有一个权威 owner。旧 `canghai-agency-shadow-ledger-v1` 本地数据不再读取或迁移；存读档、复制分支、天意干预与推进季度都只处理权威世界和必要的观察设置。
- 入世人物、未结算行动与离场收束使用独立的本地观察记录，以 seed/turn/hash 精确锚定且限制在 16KiB 内。换人不会刷新已定行动；锚点不合、数据损坏或人物不在时会安全回到普通观察，不会污染世界存档。
- 世界收藏使用独立槽位，不覆盖自动续写；开篇页与世界工具栏都可进入，支持读取、另存、重命名、复制与删除，最多 24 个命名世界。自动存档和 JSON 导出仍是可靠兜底。
- 每个世界以唯一 `mapContentVersion` 绑定精确地图 profile/revision；收藏盘会显示地图名与修订。若当前构建缺少原地图，存档会标记“地图未安装”并保留载荷，可先复制留底，不会用另一张图强行打开。
- 当前世界写入 schema 5。schema 1/2/3/4 旧档可迁移读取；迁移会先校验旧哈希，再将旧陆军兵力分配给已有角色，保持人口、粮食、财富和旧 Fact/Chronicle 不变。
- 自动存档使用合并式协调器：连续推进只保留最新一代快照、同一时间最多一次写入，并在每 8 季、空闲 5 秒、暂停、切到后台或干预后落盘。
- 本地存档不会自动跨浏览器、跨设备或跨用户同步。清理网站数据、无痕模式限制或浏览器配额不足都可能删除/阻止本地存档，因此重要世界请导出 JSON 备份。

日常检查：

```bash
npm run test:run
npm run build
npm run build:contest
npm run test:e2e
npm run test:e2e:fux01
npm run test:e2e:trim016
npm run test:e2e:trim018
npm run test:e2e:politics
npm run test:e2e:maps

npm run test:audit:politics
npm run test:audit:maps
```

需要抽查 40～64 年政治分布时，另运行 `npm run test:audit:politics:deep`；这是耗时的手动深审计，不重复塞进每次日常构建。

完整发布门：

```bash
npm run test:release
```

`test:release` 会依次执行单元/系统测试、个人版与参赛白名单构建、桌面 Chromium 试玩、1440/768/640/390 四档页面栈与移动安全区、390×844 与 640×900 移动舆图触控门、Phase A/B/C、人物 Agency、权势叙事、地方施政、双地图 80 季与 V0.3 长程审计。`npm run build:contest` 产出 `dist-contest/`：模块图会拒绝私人内容依赖，产物还会核对版本/allowlist 清单并扫描从私人 profile 派生的 328 项名称与 ID。`npm run test:e2e:contest` 另外验证参赛静态产物只提供公开地图，且遇到缺图旧档时不会覆盖原载荷。

`npm run test:audit:architecture` 用 TypeScript AST 区分 runtime/type-only 依赖，对运行时环、跨层回写、热点文件预算和类型环债务增长直接失败。v1.26.0 沿用单个 JavaScript 文件原始体积不超过 585 KiB、CSS gzip 总量不超过 40 KiB、JavaScript gzip 总量不超过 415 KiB 的既有门禁；个人版与参赛版实测 JavaScript gzip 均为 424,931 bytes、CSS gzip 均为 39,962 bytes，未提高预算。人物命途长期审计已经进入完整发布门。地图 profile 由构建注入经过校验的 HTML JSON 载荷，不进入主 JavaScript 包的解析与执行路径。`main` 与 Pull Request 会在 Node 22 环境中执行 `npm ci`、单测、架构门、双构建和关键浏览器链，失败时保留浏览器产物供复现。

`npm run test:update` 单独验证构建版本标识、游戏内手动检查、模拟新部署、更新前自动保存与移动端入口。参赛产物与源码隔离边界见 [参赛地图构建说明](./docs/CONTEST_BUILD.md)；发布任务与三主循环归属见 [Roadmap](./docs/ROADMAP_VNEXT.md) 和 [功能归属台账](./docs/FEATURE_LOOP_INVENTORY.md)。

模拟内核不使用 `Math.random`。所有不确定性都由“世界种子 + 季度 + 系统 + 实体 + 用途”独立寻址；`window.render_game_to_text()` 与 `window.advanceTime(ms)` 提供确定性的文本观察与自动化测试接口。

## 已知边界

- V1 仍是历史观察沙盒，不提供文明式胜利条件、国家直接控制、武将抽卡、即时战术或兵棋微操。
- 历史时间轴目前精确回溯有控制权差量凭证的领土格局，不是把任意旧季度的所有人口、财政、军队和市场状态完整复活；缺少差量时会显示“有缺页”。
- 世界收藏只存于当前浏览器；云存档、跨设备同步、共享世界、排行榜、在线多人和运行时生成式叙事均不在本次试玩范围。
- 海岸线由州域坐标与通行关系推导，是服务于辨识与策略阅读的架空概括图，不是精密 GIS；稀疏旧档的轮廓会更抽象。
- 桌面 Chromium 与 390×844、640×900 视口已覆盖地图主观察与四层读史路径；复杂关系图仍以桌面体验为先。Firefox、Safari 与真机系统手势尚未进入同等强度的发布回归。
- Phase B 当前完成“军权危机”“继承危机”“战争进程”和“朝堂权斗”四种 Situation 纵切、事实型结案摘要与可见持续局势；Phase C 已完成副将军权链、地方长官施政，以及朝臣派系领袖“交换朝中支持”的小纵切。POL02～POL08 已把稳定派系、真实权势账、朝堂席位、地图根基、朝堂权斗与跨入口观察收成一条线。v1.22.0 删除了不驱动模拟的通用 Goal/Plan 影子投影与本地比较账，但保留权威 `agencyDecisionSystem`、Situation 检测、关注停表、模拟规则与 schema 字段，后者将在独立权威状态审计中再决定是否收缩。
- 局势暂停只认刚结算季度中可反链到具体场面的 Situation 变化、明确结案与核心人物死亡 Fact；裸阶段变化、普通数值波动和史册关键词都不会单独停表，未受关注的局势也不会触发这条专用规则。

## 技术边界

- React + TypeScript + Vite 负责观察界面；`src/sim` 是无 DOM 依赖、数据驱动的确定性模拟内核。
- 当前仍是一个地图主页与受控卷页/抽屉组成的单页应用；本轮不为了拆代码引入路由器。天下史册等大型二级工具只会在构建分析证明有收益时设立延迟加载边界。
- 当前没有真实运行时循环依赖；`WorldState` 与 Facts/Agency/Situation 之间仍有一个 12 模块的 type-only 契约环，它不会进入浏览器 JavaScript，后续按纯 DTO 边界逐段拆解，不做一次性存档类型搬家。
- 当前版本可完全在浏览器中运行，不需要服务器。只有云存档、跨设备同步、共享世界或排行榜才需要后端。
- 存档保存世界种子、schema、权威状态、Fact 摘要链、事件摘要链和哈希；Chronicle 文案与展示阈值不是事实来源。
- 详细设计与版本落地记录见 [《东方架空历史演化模拟器 System Design Proposal》](./东方架空历史演化模拟器_System_Design_Proposal.md)。
