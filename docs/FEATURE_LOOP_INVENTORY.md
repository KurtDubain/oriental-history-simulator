# 《沧衡纪》核心体验与功能归属台账

> COMPACT01 口径，2026-09-02：游戏只把“战争进展”与“人物 / 朝堂权力”作为内容支柱；推进季度、观察世界和入世人物是使用这两类内容的交互方式。历史记录是行动结果的投影，不是独立玩法；后台模拟可以复杂，玩家入口必须少而连贯。

## 1. 两项核心内容与一种交互方式

### 战争进展

```text
政权目标与军令 → 人物部曲组成行营 / 舰队移动与预计接敌 → 战役及将领去向
→ 领土、军心、兵权与和战变化 → 下一季战争态势
```

玩家应能从地图回答“谁自带多少人、跟随谁、正去哪里、可能与谁交战、战后各自还剩多少部曲”。粮食、人口、贸易、迁徙、疾病与知识只提供军队能否持续作战的背景压力，不各自形成管理循环。

### 人物与朝堂权力

```text
经历、欲望、家族、官职 → 形成目标 → 积累支持并采取行动 → 机构回应
→ 官职、军权、关系、派系资源改变 → 新处境与新目标
```

人物必须真正做事，国家、家族、派系和军队必须回应；只展示人物属性、派系数值或历史摘要不算交付。权势优先落实到官职、军令、驻地、直属部曲、盟约与具体支持者。

### 推进、观察与入世

```text
具体事实 → 当世问题/Situation → 关注或代入 → 等待或提交一项人物行动
→ 共用 Resolver 结算 → 地图、档案、传记与世界史同步反馈 → 下一观察点
```

这不是第三套内容系统，而是玩家接触战争和权力的方式。地图、当世三问、局势卷宗、人物档案和史册是同一事实的不同阅读深度，不各自编写另一种真相。

### 共用背景压力

```text
粮食 / 人口 / 贸易 / 迁徙 / 疾病 / 知识
→ 改变地方供养、财政、军队补给、民怨与人物处境
→ 只在确实影响战争或朝局时进入默认阅读
```

这些领域继续完整模拟并保留可追溯事实，但不再扩张独立叠层、页面、胜负目标或玩家必学规则。

## 2. 现有玩家入口归属

| 现有入口 | 核心归属 | 产品角色 | 收口决定 |
|---|---|---|---|
| 顶栏季度推进、自动演化 | 交互方式 | 全局时间入口 | 保留一个入口，不把后台系统拆成分别推进的时钟 |
| 舆图“军争”与军旅档案 | 战争进展 | 核心观察 | 人物军势、临时行营、舰队、军令、行军、接敌与战役读同一权威状态 |
| 舆图“疆界”与国家朝局 | 人物与朝堂权力 | 核心观察 | 展示政权、首都、官席及地方 / 军事权力根基 |
| 舆图“供养”与地区档案 | 共用背景压力 | 按需说明 | 先回答还能否养人养兵及主要压力；不提供六套专业叠层 |
| 舆图“地势” | 交互方式 | 地理底图 | 只看山川、海岸、港口与通路 |
| 本季变化与季度总账 | 两项核心内容 | 合并入口 | 每季最多三件，只晋升具名行动、权威转折、明确结果与结案 |
| 人物、世家、列国、军旅名录 | 人物与朝堂权力 | 合并入口 | 继续共用“名录→档案”；个人部曲进入人物档案，不增加平行名册 |
| 人物所图、记忆、关系与官职 | 人物与朝堂权力 | 入世前置 | 只读权威目标、事实与处境；玩家行动进入同一 Resolver |
| 当世三问、关注、自动暂停 | 交互方式 | 故事入口 | 从当前 Situation 稳定选最多三条，不保存另一份仲裁状态 |
| Situation 局势全卷 | 两项核心内容 | 合并入口 | 首屏事实优先，不显示阶段、张力、势头或预测式审计 |
| 历史工作台、人物传记、国史、家族史 | 两项核心内容 | 结果投影 | 复用同一 Fact 场面，不把数据库浏览当作独立玩法进度 |
| 天意干预 | 交互方式 | 有限外部行动 | 保留为世界外偏转，与人物入世权限严格分开 |
| 世界收藏、导入导出 | 产品基础设施 | 辅助能力 | 留在现有二级工具，不进入玩法导航 |
| 版本与检查更新 | 产品基础设施 | 辅助能力 | 留在观察台卷末刊记，只有新版本时提示 |

## 3. 首条统一人物权力纵切

第一条代码纵切已经交付：

```text
战功、关系与家族地位形成“需要支持”的压力
→ 将领主动提携副将、联络军中同僚或请求家族背书
→ 支持来源成为可消耗、可失去、可追溯的权势资源
→ 将领请领独立军令
→ 君主/主将批准、拒绝、削权或安抚
→ 官职、军团控制、关系、声望与派系权势发生权威变化
→ 产生具体 Fact、人生记忆、Situation 转折和下一观察点
→ 玩家可继续观察，也可在已交付的身份纵切中代入人物提交同类 Intent
```

### 第一批只做这些行动

1. `联络将校`：副将投入一季心力与少量私人资财联络本军将校；成功形成可追溯军中支持，失败则只留下实际付出的成本和经历。
2. `请求背书`：人物向家主、主君或现任主将请求明确支持；对方可以支持、拒绝或暂缓，并留下关系记忆。
3. `请领军令`：复用已有 C10/C11 权威请求；支持不再只是等待数值自然达到，而来自前两项已结算行动。
4. `安抚或削权`：机构针对高风险人物作出回应；先不接入公开叛乱，避免一次铺开完整王朝循环。

### 暂不增加

- 不增加新的历史筛选页、人物百科页、派系卡片墙或独立“任务中心”。
- 不增加自由行动菜单；人物只看到与职位、目标和当前资源相符的少量行动。
- 不同时扩展海军副将、围城、宗教、文化、兵种和资源。
- 这一首批行动当时不另造 Situation；v1.18.0 才在真实权势账与朝堂行动 Fact 齐备后增加朝堂权斗，仍不新增独立入口。

## 3.1 第二条地方施政纵切

```text
粮食不足、流民、破坏、疫病、赋率与民怨形成地方压力
→ 地方长官提出开仓赈济或减免本季赋
→ AI 与玩家进入同一政权提案位和同一 Resolver
→ 州粮进入民用消耗，或国库款守恒退回地方财富
→ 动荡、人物功绩/影响与政权合法性发生权威变化
→ 同一 Fact 投影为具体史事、人物传记、人生记忆和权势得失
→ 下一季继续观察粮食支撑、人口迁出、地方安定与施政评价
```

本纵切不新增地方管理页。玩家仍从人物档案入世，每季只定一事；同一政权每季只提出一项地方措施，玩家提案替代本政权 AI 提案，但不获得成功率或裁决加成。

## 3.2 朝堂权斗纵切

```text
任免、军令、支持与盟约改变派系真实权势根基
→ 权臣形成、清洗、失势或宫变由同一政治结算写入 Fact
→ 同一政权连续两季的结构压力形成朝堂权斗 Situation
→ 国家朝局、当世问题、人物记忆、传记与史册复用同一事实
→ 下一季继续观察官席、军令、联盟与中央权威如何消长
```

本纵切没有新增“政治管理”页面，也没有新增第二套权臣值。`FactionState.power` 只是由七类真实资源重算出的排序缓存；Situation、审计与玩家解释都必须落回具体官席、地方任官、军令、家门财富、人物声望、盟约背书或派内凝聚。

## 3.3 政治观察互通

```text
明确的人物归属 / 家族在朝支点 / Fact 派系参与 / Situation 参与者
→ 纯投影得到 polityId + factionId
→ 当下派系直达国家“朝局”的同一席位与权势账
→ 可继续看真实地图根基、领袖或关系缘由
```

本纵切没有新增派系页、搜索索引或隐藏归属。只读权威 ID，不从人名、派名、摘要或传记文案猜测；历史派系已退场时保留原记录但禁止跳到另一派。因此它属于“观察与入世”的路径收口，而不是第四条玩家循环。

## 3.4 朝臣交换朝中支持

```text
冬季朝议 + 在朝官职 + 活动派系领袖身份
→ 选择同国另一支活动派系作为精确议约对象
→ 与自然朝局候选进入同一政权单席队列
→ 原政治结盟裁决复核派系、领袖、政权、凝聚与季节
→ 成功形成 faction_relation_changed 与最长四年联盟承诺
→ 双向恩义、人物传记、PersonalMemory、权势账与史册读取同一原事
→ 下一季继续观察双方官席、军令、地方根基与朝堂权斗
```

本纵切只增加人物“所图”中的一项身份行动，不新增政治管理页。玩家不获得额外分数、排序优先或资源豁免；同一政权一季最多议成一项联盟。请求在结算前失效时只留下零差量的失效结果，竞争落选则留待后议，不会用另一派或另一位领袖替换原对象。它完成了朝臣这一项 EMB05/EMB06 小纵切，但三项通用行动、家主和君主仍未全部收口。

## 3.5 v1.20.1 事件叙事减负

```text
当季具体 Fact / 结案
→ QuarterPulse 最多晋升三件真实事件
→ 当世三问用当前事实提出观察入口
→ Situation 首屏复用同一事实，相关各方按需展开
→ 普通史册过滤 situation_* 包装，只保留真实领域事件
```

TRIM02 没有增加新循环、页面或模拟领域。阶段、张力、势头和预测式结果仍可作为底层 Situation 稳定检测量，但退出默认玩家层；当季没有具体行动或权威转折时，不再用“升温”“降温”“进入阶段”制造新闻。固定世界连续 64 季审计验证默认事件、三问、Situation 与普通史册读取同一事实，桌面和移动端 E2E 覆盖事实追溯及相关各方展开/收起。此次只改变玩家投影，底层 Situation、Fact、History、存档正文与世界哈希契约不变。

## 3.6 v1.21.0 军权 / 兵权权威底座

```text
人物军事职位决定法定职权
→ 有界直属部曲提供随人的实际武装
→ 军团分别记录名义国属、正式掌令与实际拥戴
→ 战争目标、防守需要、补给、敌军与换帅形成具体军令
→ 新令当季可见、下一季执行，停战同季收回
→ 无陆路时军团赴港、水师返港装载
→ 舱单冻结出发兵力与航路，舰队逐海区航行并结算登陆或返航
→ Battle Fact 反链把军团带到战场的命令
→ 地图固定显示位置、兵力、听命对象、发令者与行军去向
```

这是 v1.21.0 的历史底座；其中“直属部曲只是正规军团内部切片”的所有权已在 v1.24.0 被下方人物军势纵切取代。仍然有效的是法定掌令与实际拥戴可分离、持久军令在下季真实执行、旧令只留 Fact/档案，以及跨海舱单与 Shipment 的守恒链。

## 3.7 v1.23.0 将领集团与战局可读性

```text
共军 / 共战 / 提携支持 / 地方与家门根基
→ 既有 FactionState 形成每国 2～4 个稳定军政集团
→ 军队按实际拥戴者所属集团归属，缺失时才回退法定主帅
→ 活动战争只读汇总集团投入、军令、战线、兵力与本季损失
→ 军争舆图区分最近一步、下一步和后续真实路径
→ 接敌与 Battle Fact 回到同一主将、集团和战后进退
```

本纵切没有增加集团状态、派系货币、战役管理页或新的季度阶段。`FactionState`、人物 `factionId`、军团法定主帅 / 副将 / 实际拥戴和原权势账仍是集团唯一权威来源。v1.23.0 当时把直属部曲视为母军团内部切片；该兵力所有权已由 v1.24.0 的个人军势取代，集团身份和命名规则不变。地图最近移动仍只在每支行营保存一条覆盖式记录；普通境内行军不进入季度大事，跨敌境、接敌、撤退、占领与登陆继续复用原有事实和史册。

## 3.8 v1.24.0 人物军势化

```text
地区人口 → 每名符合条件人物的唯一个人军势
→ 多人按战线临时组成行营，共用主将、军令、路径与补给
→ 会战仍按行营汇总结算
→ 伤亡按战前投入比例、整数守恒地分回具体人物
→ Battle Fact 冻结个人投入、伤亡、当时集团与指挥关系
→ 个人剩余部曲与战功改变人物及既有集团的军政分量
```

`PersonalForceState` 只保留兵力、凝聚、战备、驻地、当前行营和状态；不增加装备、兵种、军饷或逐人季度军事 AI。`ArmyState` 是临时行营，`soldiers` 仅是有效参与者部曲之和的派生缓存；旧“两支开局、最多三军”规则已经撤下，编队数从实际州域、战争和战线确定。舆图总览聚合人物簇，区域与近观展开人物点；同行者共用一条真实路线，簇和点都只是只读显示，不成为新模拟实体。旧 schema 4 档先验真，再守恒迁移旧军团兵力，不补写旧 Battle Fact。

## 4. 纵切完成判据

- 固定种子中至少一名人物能主动完成“积累支持→请令→机构回应”，不依赖人为修改数值。
- 至少存在获准与未准/削权两条结果路径，均由同一 Resolver 结算并能精确复演。
- 支持必须能展开到具体人物、家族、官职或军令；禁止继续使用无法解释来源的单一总值。
- 行动结果必须反馈到下一季人物目标、关系、任职与军权危机，而不是只写入一条史册文字。
- 当世三问、地图/档案速览、人物经历和局势卷宗对同一行动使用相同主语、对象与结果。
- 玩家在默认界面能回答“他想做什么、依靠谁、刚做了什么、机构如何回应、接下来观察什么”。

## 5. 新功能准入模板

以后任何功能进入 Roadmap 前必须填写：

```text
核心归属（战争进展 / 人物与朝堂权力 / 共用背景压力 / 交互方式）：
压力来源：
行动者与意图：
消耗的真实资源：
唯一 Resolver：
权威状态变化：
下一季反馈：
玩家从哪里看到/介入：
若不实现，它能否退为后台信号：
```

无法填写“行动者、Resolver、状态变化、下一季反馈”的内容，不作为新玩法开发。
